# side — две части одного приложения GSL (W+M)⁺

Владелец 13.11.2026: «из одного приложения — приложение, в котором сразу два: женское и мужское; в зависимости от
пола при входе открывается либо одна часть, либо другая». Одно приложение, один сайт, один APK, значок «GSL (W+M)⁺».

| Часть | Название | Цвет | Тексты | Сервер |
|---|---|---|---|---|
| `woman` | GSL Woman+ | розовое золото на сливе (`styles/tokens.css`) | `js/texts/woman/` | `/api/woman/…` |
| `man` | GSL Man+ | классическое золото на графите (`styles/side-man.css`) | `js/texts/man/` | `/api/men/…` |

## Как решается часть

1. Пол хранится **на сервере** в учётной записи (`users.gender`, миграция 024 в planner) и приходит в сессию
   (`account/session.js` → `gender`).
2. Пол пустой → после входа обязательный экран «Кто ты?» (`screens/gender/`). Выбор — один раз; поменять потом может
   только администратор (кабинет «Кванта» или, для себя, — настройки → «Часть приложения»).
3. Сессия старше этой сборки (поля `gender` нет) — женская: до GSL (W+M)⁺ приложение было только женским.

## Файлы

| Файл | Что делает |
|---|---|
| `side.js` | Какая часть открыта, её адрес на сервере (`api()`), ключ «чьи данные на телефоне» (`ownerKey`), оформление и тексты (`apply`, `follow`) |
| `early.js` | Обычный скрипт в `<head>`: цвет своей части ещё до первой отрисовки (без розовой вспышки у мужчин) |

## Кто спрашивает часть

- `core/i18n.js` — набор текстов (`setSide`);
- `program/source.js` — программа своей части, копия помнит, чья она;
- `sync/sync.js`, `sync/photos.js` — адреса синхронизации и фото; другая часть на телефоне = «другой человек»:
  данные прежней уже на сервере, здесь стираются и приходят свои;
- `ui/heels.js` — женская или мужская фигура утренней минуты;
- `native/native.js` — цвет виджета и будильника в APK (подписи `side`, `brand`).

Добавить что-то, что различается по частям: текст — в оба `js/texts/<часть>/*.js`; цвет — токен в `tokens.css` и
`side-man.css`; поведение — спросить `side.get()`.
